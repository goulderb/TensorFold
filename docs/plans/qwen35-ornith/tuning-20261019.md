# Qwen 35B: first measured tuning unit

The shared host sampler now scans finite greedy rows instead of allocating
and sorting the vocabulary. Commit `b8645645` changes twelve production
lines inside `lanes.sampling.choose`; callers keep the same API. This is a
verified CPU improvement. A matched full-model serving speedup has not been
measured, and the earlier full-logit numerical gate still fails. Nothing is
promoted or selected for production.

## What transfers from GLM and Flash Next

The latest GLM prompt-batching result is a useful model for qualification.
Its eight-stream cold lane-host turns improved by 20–23% after batching
routed expert work while retaining each prompt's dense/shared/KDA projection
row counts. Broader batching changed complete outputs and was rejected.
The result reduced admission skew and global forwards; it did not establish
faster steady decode kernels. The source and run are in local-ai-server's
`docs/plans/glm53-native/prefill-batch-20261018.md` and its evidence JSON,
at source `5048576c596976fd79b027a3d799a1d7b6cf0b45`.

Flash Next projects only the final prompt row through the vocabulary head
(`zig/src/families/flashnext/replay.zig`, around line 3140). Its HIP engine
also separates bounded prompt segments and graph shapes. These execution
boundaries are useful precedents. The Metal/HIP kernels, dimensions and
cache assumptions need their own Qwen CUDA implementation and proof.

For Qwen, the first cheap hypothesis is different from GLM's rejected
sub-1% top-1 packing experiment: the native Qwen adapter calls a CPU sampler
that used to sort all 248320 candidates even at temperature zero. Archived
logits let us falsify that cost without stopping production. Qwen also runs
its final norm, head and full host logit download on every prompt token,
although the adapter consumes only the final prompt row's logits. Head
elision is the next separate prefill hypothesis.

## Design and compatibility

Sol and Astra each compared an internal shared-sampler scan with a Qwen
adapter/device argmax and sampled fallback. The independent Sol judge chose
Astra's scan design, scoring it 25/25 against Sol's 22/25 on behavior,
interface depth, scope, verification and payoff. The selected implementation
uses the existing `Candidate` comparator, including the lower actual u64 ID
on equal values and signed-zero ties. It allocates nothing for aligned,
nonempty, all-finite rows with temperature at most zero.

Any nonfinite value, sampled or NaN temperature, empty input or unequal slice
length falls through to the unchanged original body. Empty and mismatched
inputs remain invalid: the old body can panic in safety builds and does not
define a result in ReleaseFast. This is path preservation, not a new promise
to accept malformed input. The test oracle is a
frozen copy of that old body; nonfinite tests preserve the pinned sort's
behavior without claiming a portable mathematical NaN ordering. Success
under an exhausted allocator is an intentional change for valid finite
greedy rows. Other allocation and error paths retain their old body.

The adapter/device alternative could eventually remove widening and the full
logit download. Today `Session.append` downloads before the adapter draws;
an adapter-only argmax would retain that cost and duplicate sampler policy.
Moving the boundary needs device reduction, logit-validity and synchronization
proof. It is deferred rather than added to this first change.

## CPU replay result

The retained harness is `tools/zig/bench_sampling_greedy.py` and its Zig
driver. It verifies the committed logit archive and each extracted member,
widens four native short/chat rows to f64, then times old greedy allocation
and sort against the actual shared `choose`. Both root and imported sampler
are explicitly optimized under the pinned Zig 0.17 compiler. An initial
prototype omitted the imported module's optimization setting. The next replay
used ReleaseSafe for both modules. Inspection of `cuda.nativeServer` then
confirmed the HTTP root is ReleaseSafe while the family/lanes modules use
the global ReleaseFast default. The authoritative replay below therefore
uses ReleaseFast on both benchmark modules, matching the sampler's mode.
Earlier numbers remain archived with their narrower build scope.

Each row has two warmup pairs and ten measured pairs with alternating order.
The result is consumed and compared in every pair. All 40 measured pairs
return equal IDs: 80 measured calls completed with no error or mismatch
abort. The harness writes its zero-error success marker only after all
calls complete; it does not retain a count of aborted failures or retries.
Any failed call or unequal pair exits nonzero without a success receipt.
The retained pre-change
control also compared the frozen baseline with the actual original sampler;
both took about 17 ms, with zero mismatches.

| Saved row | Old sort median ms (range) | Shared scan median ms (range) |
| --- | ---: | ---: |
| Native short 0 | 15.8807 (15.5523–16.7232) | 0.1718 (0.1096–0.2501) |
| Native short 1 | 15.4987 (15.4707–16.6440) | 0.1666 (0.1113–0.2456) |
| Native chat 0 | 15.2667 (15.1304–15.9267) | 0.1973 (0.1098–0.2977) |
| Native chat 1 | 14.8985 (14.7084–15.0715) | 0.2242 (0.1147–0.3142) |

The removed work is a CPU allocation and O(V log V) sort. The candidate
retains an O(V) finite-value scan; GPU execution, BF16 widening, transfer,
lane scheduling and HTTP are outside this timing. Production remained
running and the broad CPU checks were active. Windows reported 11.2% CPU
use just before the ReleaseFast replay on a 24-logical-processor host; load
was not continuously sampled. This is not an isolated-machine measurement.
The alternating comparison and large separation support this narrow result.

Existing tool turns reported about 20 decode tokens/s and 30 prompt tokens/s
with 275/331 prompt tokens and 27 output tokens. They are different runs,
not an A/B comparison for this change. Prefill dominates those short turns:
even eliminating sorting would save under 5% of their total time. A claimed
new serving rate cannot be inferred by subtracting this microbenchmark.

## Verification and remaining experiments

The allocation-free regression failed with OutOfMemory before the change.
All nine in-file sampler tests pass in Debug, ReleaseSafe and ReleaseFast. They cover
arbitrary IDs, ties, signed zeros, negative/extreme/subnormal values, seeded
BF16-widened rows, nonfinite fallback and 120 sampled-policy cases. A
separate filtered `lanes_units` run passes all 500 Python sampler cases:
60 seeds, 60 uniform sets, 300 rows and 80 row batches. The combined golden
target has a pre-existing depth-rule test call with three arguments against
the current four-argument signature; filtering the sampler isolates its
independent check without changing unrelated depth code.

The broad CPU suite succeeds at 70/70 build steps, with 1404 tests reported
passed and 109 skipped; other roots are cached. This includes shared caller
integration. Skips do not qualify missing optional codecs or model fixtures.
The generated Python sampler vectors are retained in `sampling-fixtures.zip`
with their source commit and hashes, so replay does not require the old
Python checkout. Its archived agent report predates the successful filtered
golden runs; the parent logs supersede that report's golden-test blocker.

The Windows native build passes all 60 build steps and Qwen host tests pass
47/47. The candidate is frozen locally at source
`b864564587f00f308ff9215c9870bffcd11da61f`, SHA256
`bc158ecabc478de455f6dd66f85a0f9b879770e0b05ab80ea427e5e77fb328c0`.
This executable has not been launched. The pre-change native
executable is frozen locally with SHA256
`1c9f93cebdd86f966c9bc561e62ad912a400dfbfd1c30d567f871c770330598c`
from source `ad247b3daf045015d59bd106a88591bff961e488`.

The next full-model experiment should alternate old sorting and the shared
scan against one loaded checkpoint, reset state between runs, compare every
output token, and report prefill, first-token, decode and total time. Use a
64-token prompt with at least 128 generated tokens plus a prefill-heavy tool
case; retain at least five measured pairs after warmup. Preserve the
adapter's one-token prefill append calls so the benchmark does not silently
remove per-token head/download work. A material serving candidate must show
at least 5% improvement in the chosen decode-sensitive turn with identical
complete outputs. This experiment is prepared as a protocol here; no new
full-model driver or approved outage exists yet.

After that, test explicit prefill head elision; then consider stage-major
prompt chunks and routed-expert batching. Preserve GDN/KV recurrence and
the per-row arithmetic shapes until full hidden/state/logit checks establish
safe batching boundaries. Compare final hidden rows as well as recurrent
state, following GLM's failure lessons. Concurrency, cache, long context,
soak/restart, the physical GPU floor and the independent numerical/quality
oracle remain separate promotion gates.

The previous workstation trial hour is complete. The source contract requires
fresh approval for any new production outage. CPU work and building binaries
do not qualify device behavior or authorize a launch.

## Reproduce the narrow checks

Run `tools/zig/bench_sampling_greedy.py --zig PATH_TO_PINNED_ZIG --output NEW_DIR`
with the repository Python. The default is now ReleaseFast. Pass
`--optimize ReleaseSafe` only for the separate safe-mode comparison. The
output directory must be new; each run retains raw paired samples and hashes.

For the Python goldens, extract `sampling-fixtures.zip` into a temporary
directory, set `TF_LANES_FIXTURES` to its absolute path, and run the following
from the TensorFold worktree with the pinned Zig executable:

```powershell
zig test -lc -OReleaseFast --dep lanes --dep env `
  '-Mroot=zig/tests/lanes_units.zig' -OReleaseFast `
  '-Mlanes=zig/src/core/lanes/lanes.zig' -OReleaseFast `
  '-Menv=zig/src/core/env.zig' --test-filter sampling
```

The other checks are `zig test zig/src/core/lanes/sampling.zig -lc` in each
named optimization mode, the Windows builder's `native` and
`test-qwen35-cuda-host -WithoutKernels` targets, and `zig build test -j2
--summary all`. They build binaries or run CPU tests; they do not launch the
new model. The retained native build logs count build steps, not test cases.

## Independent review

Fable 5.1 found no blocker in the sampler implementation. Its medium finding
was the original serving-mode assumption; the ReleaseFast rerun, corrected
build receipt and append-only correction row resolve it. The archived first
review read the earlier plan and safe-mode replay. Its follow-up accepted
the corrected fast-mode result, independently checked all 35 then-committed
inventory members, command flags, source hashes, sample counts and candidate
binary hash, and found no blocker.

Its low findings are recorded explicitly: replay success is enforced by
abort rather than an accumulating error counter, malformed input retains
unsafe legacy behavior, and docs/evidence need a checkpoint commit. None
establishes live performance or repairs the outstanding numerical oracle.
The follow-up's three low evidence gaps were closed by the parent: three
early unit logs were added, the unchanged baseline receipt gained a durable
location sidecar, and the actual ReleaseFast test commands were recorded.
These evidence-only follow-ups were checked by the parent, without another
independent review round. Both reviews remain archived unchanged.
